# 食べた記録を複数店舗と催事・出店先に紐づける

イベントや店舗営業でのコラボは複数店舗が提供に関わる。同じ記録を店舗ごとに複製すると、写真とメモが分かれ、件数も重複する。またラーメンWalkerキッチンや新宿地下ラーメンで何を食べたかを、提供店舗をまたいで見返したい。

食べた出来事を1件の「食べた記録」とし、順序を持つ1軒以上の提供店舗と、任意の催事・出店先を紐づける。店舗営業のコラボもイベントのコラボも同じ関係で表す。実際の店舗訪問を意味しないため、画面では「訪問ログ」「訪問日」「訪問状況」を「食べた記録」「食べた日」「記録の有無」に改める。技術上の Visit 型と visits パスは継続する。

催事・出店先はIDと名前を持つ。入力の前後の空白を除去し、同名のデータを保存トランザクション内で再利用する。大文字・小文字や名前の内部の空白は変更しない。名前を押すと、その出店先の記録を新しい順に表示する。住所・座標・開催期間と管理用CRUDは追加しない。

`visit_log_shops` が記録と店舗を結ぶ唯一の関係となる。主店舗は持たず、記録の作成は `POST /auth/visits` に統一する。各店舗の件数、お気に入り度、代表写真と削除制約はこの関係から導出する。記録を削除すると、すべての提供店舗から同じ記録が消える。

移行00016は既存のID・日付・お気に入り度・メモ・作成更新日時を引き継ぎ、メニューと画像を同じIDの記録に保持する。旧催事名は空白だけの値を除き催事・出店先に移す。旧データの存在しない店舗への参照は削除せず、従来どおり起動時に報告する。施設名で登録済みの店舗は、提供店舗を推測して自動変換しない。

公開APIは非公開メモを省略し、ブラウザの記録キャッシュは認証ユーザー別に分ける。記録と画像の変更後は、関連が外れた店舗を含め店舗・出店先の記録と店舗一覧を更新する。画像のアップロード状態は共通の記録IDで追跡する。

写真取り込みの自動再開と日付不明記録への日付付与は、提供店舗がその1軒だけの記録に限定する。コラボの共通写真数を店舗別の取り込み済み枚数として扱うと別店舗の写真を飛ばすため、共有記録を自動で再利用しない。
