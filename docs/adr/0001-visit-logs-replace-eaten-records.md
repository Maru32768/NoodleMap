# 「食べた」記録を訪問ログに置き換える

「食べた」と評価は店舗に1つの記録 (`eaten_shops`) として持っていたが、同じ店に何度も行った記録や、訪問ごとの評価・メニュー・写真を残せなかった。そこで訪問ログを唯一の記録とし、「食べた」は訪問ログが1件以上あること、店舗の評価は評価が付いた最新の訪問ログの評価、という導出値に変えた。既存の `eaten_shops` の各行は訪問日不明の訪問ログ1件に変換して評価を引き継ぎ、`eaten_shops` は削除する。このため訪問ログの訪問日は任意で、訪問日不明のログは最も古いものとして扱う。

## Considered Options

- `eaten_shops` を残し、訪問ログを追加するだけにする: 「食べた」と評価が2か所に存在し、どちらが正しいかがずれるため採らなかった。
- 移行時に既存の記録を捨てる: 個人の記録が失われるため採らなかった。

## Consequences

- 記録は今までどおり店舗に1つ (ユーザー単位ではない) で、管理者が書き、誰でも読める。ただし非公開メモは管理者以外への応答に含めない。
- 訪問ログを持つ店舗は削除できない。

※ その後「評価」は「お気に入り度」に改称した (GLOSSARY.md 参照)。

※ 記録と店舗の関係・呼称は [食べた記録を複数店舗と催事・出店先に紐づける](0002-shared-eating-records-and-venues.md) で更新した。
